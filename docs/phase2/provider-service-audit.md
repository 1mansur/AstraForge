# Provider transport and desktop dispatch

## Reproduced provider failures

Real HTTP fixtures bind an ephemeral loopback port, consume a real request and write controlled responses. They do not contact a paid provider. Before changes, four of six tests failed: an EOF without a completion marker was accepted as a complete action; a repeated SSE event ID duplicated generated text; `finish_reason: length` was accepted as success; and mixed embedding dimensions were accepted. A strengthened cancellation test waited until response headers had arrived before cancelling. It then failed because the blocking body read kept the worker waiting for the stalled socket. The server was explicitly released after the deadline to avoid leaving a test thread behind.

The provider keeps its synchronous public traits and runs asynchronous reqwest transport on one process-lifetime Tokio runtime, initialized through `OnceLock`. The runtime has two async worker threads and at most four blocking threads. A 20 ms cancellation poll wakes stalled request/header/body waits and drops the caller's future. Connect and total request limits remain 10 and 60 seconds. Clients are constructed within each operation and use a shared bounded DNS resolver; cancellation never drops a private runtime that could wait indefinitely for an OS DNS call.
DNS resolution reserves one of four slots before scheduling blocking `ToSocketAddrs` work. The slot's lease stays inside the blocking closure until the OS call returns, including after its async waiter is cancelled. Saturation fails immediately instead of queueing more resolver work, and dropping an unpolled resolver future releases its reservation. OS `getaddrinfo` cannot be forcibly aborted: up to four abandoned resolutions can remain blocked until the OS returns, and new hostname-based requests can fail while those slots remain occupied. This is a resource bound, not a claim that transport cancellation immediately reclaims every OS resource.

The incremental SSE decoder validates UTF-8 across chunk boundaries, handles CRLF and multiline event data, and requires `[DONE]` or a completed `stop` frame before treating EOF as successful. Truncation, provider error frames, conflicting event IDs and unsupported native tool calls return explicit protocol errors. Null tool fields and an empty `tool_calls` array are accepted as no invocation; nonempty or malformed invocations remain rejected. Identical explicitly identified events are deduplicated. Limits are 256 KiB per line/event/generated response, 4 MiB total wire data, 256 bytes per event ID, and 4,096 identified events. Usage data is retained. Embeddings retain their 32-input/128 KiB request and 4 MiB response limits, validate dimensions consistently across a batch, and recheck cancellation after decoding.

Seven HTTP adversarial tests cover those regressions, stalled headers, connection failure, HTTP 400/401/403/429/500, invalid JSON, invalid UTF-8 and oversized frames. Provider bodies and input text are not exposed in transport errors. The existing successful streaming/embedding tests remain in the full suite. Generated parser properties and configured fuzz targets are reported separately; they are not a substitute for these socket tests.
Four resolver lifecycle unit tests use controlled blocking closures rather than changing host DNS or contacting a DNS service. They verify the shared runtime, unpolled cancellation, completion/error cleanup, and cancellation of four active waiters while all four blocking leases remain occupied. One thousand additional attempts are rejected without starting work; releasing the controlled lookups restores capacity. Two SSE regressions cover null/empty tool fields and rejection of real or malformed invocations before text emission. The targeted provider run passed all seven selected tests, including the existing endpoint-policy test, in 0.01 seconds.

## Desktop contract and lifecycle

The Tauri boundary now requires protocol version 1 and a repository identity for repository-scoped methods. A request captures one Workspace and uses it throughout dispatch, including agent session ownership and resumes. Old repository IDs fail before mutation; command IDs are also checked against their owning repository. Global methods are documented in `docs/protocol.md`, and shared golden fixtures are exercised from both languages.

Index and search requests share one cancellation registry with at most 32 active or pending operations across both kinds. Each request registers a fresh token, captured repository identity and method before attempting its `operation_log` admission write. A cancellation signal therefore reaches an operation already waiting for the database connection, and dispatch checks the token before starting work. Finished tokens are weakly held and removed when the registry is next accessed. Cancellation selects the captured repository and operation kind; semantic cancellation does not silently fall back into a new text search.

Full indexing claims its running state while holding the same lifecycle mutex used by repository opening. A scope guard releases the running flag on normal return, error or unwinding panic. `cancel_index`, `cancel_search`, `stop_command` and `stop_agent` bypass operation-log writes. Index/search cancellation can set tokens while a database query owns the connection, allowing its SQLite progress handler to observe the signal. Command and agent stop retain repository ownership checks before stopping their target; this logging bypass does not remove their own state persistence or guarantee that every stop path is free of database waits.

Watcher callbacks receive a stop token and capture a repository generation. They check that generation before work and before updating vectors/emitting events. Events carry version, repository identity and a global sequence. The frontend guards its own asynchronous continuations and reconciles sequence gaps; the transport is not claimed to deliver callbacks in strict order.

Interrupted patch conflicts previously prevented opening the repository at all. The host now returns the conflict with the opened repository, allows inspection and blocks mutations while a journal remains. Recovery preserves external changes. Resolving the files and reopening retries the existing journal recovery; this does not add automatic conflict resolution.

## Diagnostics and validation

The local `operation_log` records UUID, repository, method, start time, duration, status and error code. Request payloads are excluded. Completed history is bounded at 10,000 entries and unfinished operations become interrupted on startup. A failure to persist the final log emits a diagnostic without converting an already successful file mutation into a retryable operation error. The diagnostics view includes operation and subsystem records. Cancellation control signals avoid the logging lock path.

Service integration tests use real temporary Git repositories and the real native watcher. They verify incompatible/missing/stale envelopes cannot create files; journal conflicts allow reads but preserve content against writes; recovery succeeds after explicit resolution; events are scoped/versioned across repository switches; and interrupted operation records recover on restart without recording file contents.

## Limits

- No paid model endpoint was exercised. Provider-specific behavior outside the compatible chat/embedding contract remains unverified.
- Repeated identical token text without explicit event IDs is legitimate and cannot be safely deduplicated. Arbitrary event reordering is rejected where detectable, not reconstructed.
- Cancellation is cooperative during synchronous JSON/AST/SQLite work and filesystem calls. The 20 ms transport poll is not a universal end-to-end latency guarantee.
- The synchronous provider traits are invoked from native blocking workers. Calling them directly from an already-running Tokio runtime is not a supported adapter pattern.
- Versioned repository IDs and UI generation guards address stale dispatch; they are not an OS sandbox or protection from trusted code that can call internal Engine APIs.
- Operation records do not measure peak resident memory or native UI rendering. Those measurements and their scope are documented separately.

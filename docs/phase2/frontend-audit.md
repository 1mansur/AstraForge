# Phase 2 frontend adversarial audit
## Baseline and method
The unchanged Phase 1 frontend passed 32 tests, full TypeScript checking, ESLint and the production build. Initial sandboxed test/build attempts failed because esbuild could not access an ancestor directory; the unchanged commands passed with the required filesystem access. Validation used Node 24.19.0, React 18.3.1, Vitest 3.2.7 and jsdom with at most two workers.
Five targeted regression tests were run before their fixes. All five failed: duplicate file opening discarded a draft, overlapping invalidations left an older disk version visible, an old repository diff populated a new repository, watcher notifications multiplied concurrent requests, and diff rendering mounted every source line. The raw task logs are `work/phase2/frontend-before.txt` and `work/phase2/frontend-after.txt` in the delivery workspace. These working logs are not runtime dependencies.
## Reproductions and fixes
| Failure | Reproduction and cause | Fix and regression evidence |
| --- | --- | --- |
| Draft loss on duplicate open | Start two reads of one file, resolve the first, edit, then resolve the second. The second completion replaced the existing document. | One pending read per path; an existing document is never replaced by another open. Latest navigation intent determines focus. |
| Stale external-change state | Two change events capture hash H0. Resolve reads as H1 then H2. The old implementation discarded H2 because H1 had changed the captured hash. | One reconciliation batch runs at a time; pending paths coalesce. Each later batch reads against the current buffer. Dirty drafts and edits made during reads are preserved. |
| Cross-repository results | Delay repository A's diff, open B, then resolve A. Unguarded completions populated B. | Every scoped bridge request captures repository identity and controller generation. Old results and subsequent workflow steps are cancelled. Pending mutations block switching; duplicate command execution is rejected. Backend repository binding remains the authoritative boundary. |
| Reordered views and agent polls | Resolve older graph/diff/status reads last, or resolve a running-agent poll after Stop completed. | Resource request generations reject older views; agent transition revisions prevent stale polls from reviving cancelled sessions. |
| Missing event contract and event storms | Old events lacked version, repository identity and sequence. Repeated notices each launched reads and Git operations. | Version 1 envelopes, runtime decoding, repository filtering, duplicate/old sequence rejection, and gap-triggered reconciliation. A bounded path set and one reconciliation worker cap outstanding work. Diagnostic and other-repository events advance the shared sequence. |
| Subscription leak | Dispose while native event registration is still awaiting completion. The late unlisten function was retained after disposal. | Lifecycle checks and idempotent cleanup release late subscriptions. Initialization is idempotent and does not replace settings saved while initial settings were loading. |
| Unbounded output fragments | Repeated polls each return many tiny chunks. A character cap alone allowed hundreds of thousands of retained chunk objects and rendered spans. | Each process retains at most 500,000 characters and 2,048 chunks. At most 128 terminal sessions remain; completed drained sessions are evicted first. Invalid/reordered process snapshots are rejected. Final output continues draining after process exit. |
| Large diff and Git list rendering | A 30 KB diff containing 10,000 short lines created 10,000 DOM rows. An 8 MiB permitted diff could contain many more. | Git and patch diffs render a viewport window backed by compact line offsets. Git change lists are virtualized. A 200,000-line adversarial diff remains navigable and repository text remains escaped. |
| Scroll-event lifetime | Deferred React state updaters read `event.currentTarget` after the event handler returned. Batched scrolling crashed the list. | Capture the numeric scroll offset synchronously in the existing virtual list and new diff view. Tests exercise batched scrolling and shrinking results. |
| Command argument corruption | Saving an unrelated setting dropped empty arguments and changed quoted/spaced Windows paths because JSON formatting and the command parser used different grammars. | A reversible argument formatter shares the parser's grammar. Five hundred deterministic argument arrays roundtrip exactly; a component test saves appearance while preserving the configured argument vector. Build commands also parse quoted executable paths. |
| Reload/delete draft race | Edit a buffer after confirming reload or while deletion is awaiting completion. The completion previously discarded the later draft. | Reload refuses to overwrite the changed buffer. Deletion preserves a subsequently edited buffer and marks it conflicted. |
| Settings and recovery disclosure | The context-budget form accepted values rejected by Rust. Recovery conflicts could be opened without displaying their cause. | Form bounds match 2,048–64,000. A non-null native `recoveryRequired` result is surfaced immediately while inspection remains available. |
## Measurements and regression budgets
Measurements below are actual jsdom/controller runs on the development host with other work in progress. They measure JavaScript and DOM construction, not native WebView layout, paint, interaction latency or whole-process peak memory. Timing variation is expected; tests enforce structural bounds rather than arbitrary wall-clock thresholds.
| Fixture | Before | After |
| --- | --- | --- |
| 1,000 change events while the first read is pending | 3,000 immediate IPC requests, including 1,000 reads; 6.61 ms dispatch | 3 immediate requests, including 1 read; 2.53 ms dispatch; later events coalesce into another batch |
| Mount a 10,000-line diff | 10,000 mounted rows; 348.91 ms | 36 mounted rows; 88.51 ms |
| 500 polls containing 500,000 alternating one-character output chunks | Not measured before the fix | 2,048 retained chunks; 82.57 ms cumulative processing |
The diff budget is the visible viewport plus overscan, independent of total line count. The fixture's 600 px viewport renders 36 initial rows. Invalidation work has at most four reconciliation operations active; a Git refresh internally has two requests. Pending invalidation paths are capped at 4,096 and overflow becomes a full reconciliation. Per-event path content is bounded and malformed or incompatible events produce a diagnostic instead of entering state.
## Final frontend evidence and limits
The frontend suite passes 74 tests across nine files, including shared Rust/TypeScript protocol examples, 2,000 deterministic malformed JSON cases, 500 argument roundtrip cases, command authorization, stale-state scheduling, disposal, bounded output, large diff/list navigation and settings persistence. The final recorded test duration was 13.03 seconds. TypeScript includes dependency declarations; ESLint and the whole-source style check pass. `pnpm build` passed in 120.38 seconds including TypeScript; Vite reported 1 minute 39 seconds. The shell is 276.31 kB before gzip, while Monaco remains a separate 3,294.04 kB bundle with its large-chunk warning unsuppressed. No tests or compiler warnings were disabled.
The bridge golden tests validate serialization against `fixtures/protocol-v1.json`; controller tests inject delayed native responses to exercise real controller logic. They do not substitute for actual native IPC integration. Monaco workers, native window interaction, accessibility, graphics/layout performance and live-provider behavior still require their own validation. Open editor buffers and expanded folder caches remain retained for the current workspace; this audit does not claim a total renderer-memory ceiling. Semantic search remains bounded to 100 ranked results. Production build and final whole-repository validation are recorded with the Phase 2 delivery report.
## Companion Rust protocol and stream smoke
The [protocol property suite](../../crates/core/tests/protocol_properties.rs) passed five tests in 0.16 seconds after a 22.20-second incremental test build. It executed exactly 4,500 generated cases: 1,000 valid UTF-8/SSE streams using two byte-fragmentation strategies each, 500 conflicting duplicate-event IDs, 2,000 bounded arbitrary byte sequences, and 1,000 invalid envelopes checked against a real Engine and temporary SQLite database. One additional static test loads the shared desktop protocol examples. Seeds are fixed in the source and printed in `work/phase2/protocol-properties.txt`; the run logged an environment path-canonicalization warning without failing compilation or tests.
These are deterministic property smoke tests, not a coverage-guided fuzz campaign. The configured protocol fuzz target now includes `RequestEnvelope`; the additional [stream fuzz target](../../fuzz/fuzz_targets/stream.rs) checks bounded decoder output and equality between emitted deltas and the final completion. Whether a coverage-guided target was built and run is reported separately in the Phase 2 validation record; supplying a target alone is not recorded as executing it.

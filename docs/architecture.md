# Architecture
Phase 2 preserves these boundaries. The initial assessment below records the original bootstrap; the current hardening changes and evidence are in [the engineering report](engineering-report.md).
## Initial assessment
The supplied workspace contained only empty work/ and outputs/ directories. There was no existing framework, application, reusable component, package manager configuration, test suite or UI convention. Node and Git were available. Rust and a Windows C++ toolchain were absent. The implementation therefore introduced a new pnpm frontend and Cargo workspace, without replacing existing behavior.
## Boundaries
React views under src/ui consume domain-specific stores and the Workbench controller under src/state. The typed Bridge in src/services translates requests to one Tauri command. UI code never reads or writes repository files or starts OS processes directly; session imports read only the archive explicitly selected through the file chooser. Monaco runs local workers; no editor code is loaded from a CDN.
The small src-tauri host initializes application data, emits bounded filesystem/diagnostic events and runs blocking domain operations away from the UI thread. The astraforge-core crate has no dependency on Tauri or React and is integration-tested directly.
Engine in service.rs routes a typed request enum through a versioned desktop envelope. Repository-scoped calls capture an immutable Workspace, and events carry repository identity and sequence. It owns separate repository, indexing, patch, process, vector and agent services. Filesystem capabilities, database ownership and command policies remain in the backend even if the UI is compromised.
## Storage and files
Database serializes SQLite access, uses WAL, busy timeouts, migrations and transactions, rejects future schema versions and holds an exclusive file lock for the app database lifetime. Schema creation for domain-owned tables is idempotent. Database state includes repositories, settings, index documents/symbols/references/edges, vectors, sessions, tool calls, command/test runs, patch sets/journals and diagnostics.
Workspace pins a capability directory. Relative paths are checked component by component; symlinks, reparse points, Git metadata, Windows aliases, device names and traversal are rejected. Text reads cap at 2 MiB and require UTF-8. Editor saves verify SHA-256. Normal app mutations are serialized.
Patch proposals persist before approval. Applying first checks every precondition, writes a durable journal, performs capability-rooted replacements and records completion. Failure rolls back completed writes where their current content matches the expected intermediate content. Recovery preserves externally diverged content and reports a recovery-required state instead of overwriting it.
## Index and graph
LanguageAdapter abstracts parser/extractor behavior. Tree-sitter supplies real syntax trees for TS/TSX/JS/Rust/Python/JSON; pulldown-cmark supplies Markdown structure. Invalid source can produce partial symbols with parse-error reporting. Reference results are syntactic name matches, not compiler-resolved identities.
The indexer reads Git's tracked and unignored paths. One serialized indexing worker processes bounded batches of 64 documents and persists changes transactionally. A watcher coalesces paths through a bounded channel; directory changes reconcile descendants. A queue overflow explicitly requests reconciliation. Indexing does not create one task per file.
Dependencies have indexed source and target lookup; graph traversal uses queues and visited sets, with node/edge caps. Relative module resolution is heuristic. Package aliases, Rust macros and language-specific type inference need future language-server adapters.
## Process and Git services
Commands use executable paths plus argument arrays, never string-concatenated shell commands. Safe Git forms use an argument grammar. Unrecognized programs, test runners and shells require explicit approval. System-administration programs are blocked. The environment is reconstructed from a small allowlist, excluding provider secrets by default.
Each command has bounded output, sequence-numbered polling, persisted completion, stdin and cancellation. Windows Job objects own process trees. The service is a pipe-based console; ConPTY is a replaceable future transport.
Git operations use the CLI with paging, hooks, fsmonitor and external diff/textconv disabled where relevant. Literal paths and explicit separators prevent option/pathspec injection. Operations have bounded output and execution time.
## Agent architecture
ChatProvider and EmbeddingProvider isolate transport. CompatibleProvider implements bounded incremental SSE over HTTPS or loopback HTTP, using a named environment variable for credentials and disabling redirects. Synchronous domain workers drive async request futures on a shared bounded Tokio runtime; cancellation interrupts stalled request reads and DNS capacity is independently bounded. VectorStore persists vectors and performs streaming top-k cosine search with repository/provider filtering and indexed-file hash validation. This exact search is linear in stored vectors and intended as a replaceable initial vector backend.
AgentManager persists sessions and typed tools. Every tool attempt records ID, arguments, timing, result and status. The graph contains public plans, generation results, tool observations, approval nodes and errors. It stores public execution data, not hidden model reasoning. Recent tool results and relevant symbols are selected under a bounded request budget. Commands and patches have separate explicit approval paths. An agent cannot set its own approval flag.
Repository memory is keyed by repository; session memory is the persisted task/trace. Both remain untrusted data. The repair process is bounded by configured steps and three patch proposals, with approvals between mutations and command execution.
## Extension and migration
Replace a provider by implementing its trait; add parser adapters by implementing LanguageAdapter; change vector storage behind VectorStore; keep existing module APIs when replacing Git, process or database implementations. Frontend stores consume contracts rather than implementation details. These boundaries avoid changing unrelated UI code for backend replacements, although database interfaces currently expose SQL to domain services and a non-SQL backend would require a repository layer.
For persistent changes, increment SQLite user_version, reject unsupported future versions and migrate inside a transaction before services start. Preserve version 1 session readers or add explicit import converters. New commands require changes to both Rust Request and TypeScript Methods plus contract tests. Existing schema export can be regenerated with cargo run -p astraforge-core --example export_contracts -- docs.
